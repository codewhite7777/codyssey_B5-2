01 · 자료구조

그래프

점(노드)과 그 점들을 잇는 선(간선)으로 "무엇과 무엇이 연결돼 있나"를 표현하는 구조.

쉬운 비유

지하철 노선도. 역이 점, 역과 역을 잇는 철로가 선이에요. 친구 관계도(사람 = 점, 친구 사이 = 선)도 그래프죠.

왜 필요해?
  • Git 이력은 커밋끼리 이어진 그래프예요.
  • LOG, PATH, ANCESTORS는 전부 이 그래프를 돌아다니는 일이에요.
특징
  • 선에 화살표가 있으면 방향 그래프
  • 점마다 "이웃 목록"을 저장 (인접 리스트)
  • Mini Git은 parents, children 두 목록

02 · 자료구조

트리 · 커밋 트리

뿌리 하나에서 가지가 갈라져 나가는 그래프. 모든 점의 부모가 딱 하나(뿌리만 0개)예요.

쉬운 비유

나무를 거꾸로 세운 모양, 또는 회사 조직도. 맨 위 대표(뿌리) 아래로 팀이 갈라지고, 팀원 한 명의 상사는 한 명뿐이에요.

왜 필요해?
  • merge가 없는 이번 과제에서 커밋 이력은 항상 트리예요.
  • BRANCH로 가지가 생기고 COMMIT으로 가지가 자라요.
특징 · 용어
  • 뿌리(root): 부모 없는 첫 커밋
  • 잎(leaf): 자식 없는 끝 커밋
  • 깊이: 뿌리에서 몇 칸 내려왔나
  • 브랜치 = 커밋을 가리키는 이름표, HEAD = 지금 서 있는 브랜치

03 · 자료구조

DAG와 사이클

DAG = 화살표에 방향이 있고(Directed), 따라가도 제자리로 돌아오지 않는(Acyclic) 그래프.

쉬운 비유

족보. 할아버지 → 아버지 → 나 순서로만 이어지고, 내가 할아버지의 아버지가 되는 일은 없어요. 그런 "고리"가 바로 사이클이에요.

왜 필요해?
  • 사이클이 있으면 "부모 먼저" 순서(LOG)를 정할 수 없어요.
  • 조상 찾기가 끝나지 않아요.
  • 과제 요구사항: 커밋 그래프는 DAG여야 함
특징
  • 트리는 DAG의 한 종류 (부모가 1개인 DAG)
  • merge 커밋(부모 2개)이 생겨도 DAG는 유지
  • 위상 정렬은 DAG에서만 가능

04 · 자료구조

해시맵 (딕셔너리)

키로 "칸 번호"를 계산해서, 처음부터 훑지 않고 그 칸으로 바로 가는 저장 방법.

쉬운 비유

사물함. 이름표를 보면 몇 번 사물함인지 바로 알아서 그 칸만 열어요. 리스트는 사물함을 1번부터 하나씩 다 열어 보는 방식이에요.

왜 필요해?
  • commits[hash]로 커밋을 바로 찾기
  • 새 hash가 이미 있는지 바로 확인 → 중복 방지
  • 역색인도 해시맵으로 만들어요
특징
  • 찾기·넣기·있는지 확인: 평균 O(1)
  • 리스트에서 찾기: O(N)
  • 파이썬의 dict, set이 해시맵

05 · 자료구조

큐 (Queue)

뒤로 들어가서 앞으로 나오는 줄. 먼저 들어온 것이 먼저 나와요.

쉬운 비유

편의점 계산 줄. 먼저 온 손님이 먼저 계산하고, 새 손님은 줄 맨 뒤에 서요.

왜 필요해?
  • BFS와 위상 정렬이 "다음에 처리할 것"을 큐에 줄 세워요.
  • 먼저 발견한 것을 먼저 처리해야 가까운 순서가 지켜져요.
특징
  • FIFO: First In, First Out
  • 파이썬은 collections.deque
  • 넣기 append, 꺼내기 popleft 모두 O(1)

06 · 알고리즘

BFS (너비 우선 탐색)

가까운 곳부터 한 겹씩 넓혀 가며, 연결된 점을 하나도 빠뜨리지 않고 둘러보는 방법.

쉬운 비유

호수에 돌을 던지면 물결이 동그랗게 퍼지죠. 바로 옆(1겹)을 먼저 다 적시고, 그다음 2겹, 3겹으로 가요.

왜 필요해?
  • 연결된 모든 점을 빠짐없이 찾을 때
  • 같은 점을 두 번 보지 않게 할 때
  • "몇 칸 떨어졌나"가 덤으로 나와 최단 경로의 바탕이 돼요
특징
  • 큐 + visited(방문 표시) 집합
  • 가까운 순서(거리 순)로 방문
  • 시간 O(V+E): 점 수 + 선 수

흔한 실수: visited 표시를 큐에서 꺼낼 때 하면 같은 점이 줄에 여러 번 서요. 큐에 넣을 때 바로 표시하세요. (위 그림의 E는 B와 C 둘 다의 이웃이지만 한 번만 들어가요.)

파이썬 코드 보기 Mini Git: graph.py · bfs_order() 
from collections import deque

def bfs(graph, start):
    visited = {start}          # 넣을 때 바로 "방문함" 표시
    queue = deque([start])     # 줄 서기
    order = []
    while queue:
        node = queue.popleft()     # 맨 앞에서 꺼내기
        order.append(node)
        for nxt in graph[node]:    # 이웃 하나씩 보기
            if nxt not in visited:
                visited.add(nxt)
                queue.append(nxt)  # 맨 뒤에 줄 세우기
    return order

07 · 알고리즘

최단 경로

BFS를 돌리면서 "누가 나를 데려왔는지"를 적어 두고, 도착하면 그 기록을 거꾸로 따라가는 방법.

쉬운 비유

지하철에서 "정거장 수가 가장 적은 길" 찾기. 1정거장 거리 역을 다 표시하고, 2정거장, 3정거장… 목적지가 처음 표시되는 순간이 가장 가까운 거리예요.

왜 필요해?
  • Mini Git PATH: 두 커밋이 이력상 몇 칸 떨어졌는지
  • 경로가 없으면 No path
특징
  • 모든 선의 비용이 똑같이 1일 때만 정답
  • 비용이 다르면 다익스트라가 필요
  • 시간 O(V+E)
파이썬 코드 보기 기본형 (prev 기록) 
def shortest_path(graph, start, goal):
    prev = {start: None}        # 누가 나를 데려왔나
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            break
        for nxt in graph[node]:
            if nxt not in prev:
                prev[nxt] = node
                queue.append(nxt)
    if goal not in prev:
        return None                 # No path
    path = []
    while goal is not None:     # 도착점에서 거꾸로
        path.append(goal)
        goal = prev[goal]
    return path[::-1]

08 · 알고리즘 · Mini Git 방식

PATH 사전순 규칙

최단 경로가 여러 개면 "hash1->hash2->… 문자열이 사전순으로 가장 작은 경로"를 골라야 해요. 거리를 도착점에서 먼저 재고, 출발점부터 가장 작은 hash를 골라 걸어가요.

쉬운 비유

내비게이션에 "남은 거리"가 칸마다 적혀 있다고 생각해 보세요. 갈림길마다 남은 거리가 1 줄어드는 길 중 이름이 가장 앞(가나다순)인 길로 가는 거예요.

왜 이렇게 해?
  • 과제 규칙: 길이가 같으면 사전순 최소
  • "남은 거리"를 알면 한 칸씩 가장 작은 hash만 골라도 된다
특징
  • BFS 1번 + 걸어가기 1번 → O(V+E)
  • hash 길이가 모두 7로 같아서 칸 단위 비교 = 문자열 비교
  • 코드: graph.py · shortest_path()

언제 실제로 생기나: 같은 길이의 경로가 여러 개 생기려면 merge(부모 2개)가 필요해요. 이번 과제는 merge를 안 만들어서 CLI로는 이 상황이 안 생기지만, 규칙은 코드에 구현돼 있고 EVALUATION.md 1-4에 직접 확인하는 명령이 있어요. 그림은 hash를 2글자로 줄였어요.

09 · 알고리즘

조상 탐색

부모 쪽 화살표만 따라 끝까지 올라가는 BFS. BFS 코드에서 "이웃 = 부모"로만 바꾸면 돼요.

쉬운 비유

족보 거슬러 올라가기. 나 → 부모님 → 조부모님. 형제나 사촌은 "위로" 올라가서 닿는 사람이 아니니 조상이 아니에요.

왜 필요해?
  • Mini Git ANCESTORS
  • "이 커밋에 어떤 변경들이 다 들어 있나?" = 조상 전부
특징
  • 방향이 있는 BFS (부모 방향만)
  • merge 때문에 같은 조상을 두 길로 만날 수 있음 → visited 필수
  • 형제 가지는 절대 안 나옴
파이썬 코드 보기 Mini Git: graph.py · find_ancestors() 
def ancestors(parents, start):
    visited = {start}
    queue = deque([start])
    result = []
    while queue:
        node = queue.popleft()
        for p in parents[node]:      # 부모 쪽으로만!
            if p not in visited:       # 두 길로 만나도 한 번만
                visited.add(p)
                result.append(p)
                queue.append(p)
    return result

10 · 알고리즘

위상 정렬

"먼저 해야 하는 것"이 항상 앞에 오도록 줄을 세우는 방법. 조건이 다 풀린 것부터 하나씩 꺼내요.

쉬운 비유

수강신청의 선수과목. "자료구조"를 들어야 "알고리즘"을 들을 수 있죠. 남은 선수과목이 없는 과목만 지금 들을 수 있어요.

왜 필요해?
  • Mini Git LOG: 부모가 자식보다 항상 먼저
  • 시간순은 시계가 틀리면 깨지지만, 이건 관계로 정해서 안 깨져요
특징
  • 진입 차수 = 먼저 나와야 할 것의 개수
  • 진입 차수 0인 것만 꺼냄 (Kahn 알고리즘)
  • 사이클이 있으면 불가능, 시간 O(V+E)

이 그림의 화살표 = "이게 먼저" (부모 → 자식). 조상 탐색 그림과 방향이 반대예요. 같은 그래프를 어느 쪽에서 보느냐의 차이예요.

파이썬 코드 보기 Mini Git: graph.py · topological_order() 
def topological_order(nodes, parents_of, children_of):
    indegree = {n: len(parents_of(n)) for n in nodes}  # 부모 수
    queue = deque(n for n in nodes if indegree[n] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for child in children_of(node):
            indegree[child] -= 1
            if indegree[child] == 0:     # 조건이 다 풀렸다
                queue.append(child)
    if len(order) != len(indegree):
        raise ValueError("cycle detected")
    return order

11 · 알고리즘

병합 정렬

반으로 계속 쪼개 1개씩 만든 다음, 정렬된 두 줄을 맨 앞끼리 비교하며 하나로 합쳐 올라가는 방법.

쉬운 비유

시험지 묶음을 이름순으로 정리할 때 둘로 나눠 두 사람이 각자 정리해요. 그다음 두 묶음의 맨 위 장끼리만 비교해서 앞인 것을 내려놓으면 금방 합쳐져요.

왜 필요해?
  • 과제가 sorted(), .sort()를 금지해요
  • 입력이 어떻든 항상 빠름 (최악도 O(n log n))
  • 안정 정렬: 같은 작성자 커밋은 만든 순서 유지
특징
  • 분할 정복 + 재귀
  • 평균·최악 O(n log n), 메모리 O(n)
  • 값이 같으면 왼쪽 먼저 → 안정

흔한 실수: 값이 같을 때 오른쪽을 먼저 넣으면 안정성이 깨져요. 27과 27′(값은 같고 원소는 다름)이 끝까지 순서를 지키는지 보세요. 실제 코드는 왼쪽 절반을 끝까지 먼저 처리하지만, 그림은 보기 쉽게 층별로 보여 줘요.

파이썬 코드 보기 Mini Git: sorting.py · merge_sort() 
def merge_sort(items, key):
    if len(items) <= 1:
        return list(items)            # 1개는 이미 정렬됨
    mid = len(items) // 2
    left = merge_sort(items[:mid], key)
    right = merge_sort(items[mid:], key)
    return _merge(left, right, key)

def _merge(left, right, key):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if key(right[j]) < key(left[i]):   # 오른쪽이 "더 작을 때만"
            result.append(right[j]); j += 1
        else:                               # 같으면 왼쪽 먼저 → 안정
            result.append(left[i]); i += 1
    return result + left[i:] + right[j:]

역색인 (Inverted Index)

"단어 → 그 단어가 나오는 커밋 목록"을 커밋할 때 미리 적어 두고, 검색할 때는 꺼내기만 하는 방법.

쉬운 비유

책 맨 뒤의 "찾아보기". '해시' 항목을 보면 몇 쪽에 나오는지 바로 알 수 있어서 책 전체를 넘겨 볼 필요가 없어요.

왜 필요해?
  • 과제 요구: 검색할 때 모든 커밋을 훑지 말 것
  • SEARCH <단어>, SEARCH --author=
특징
  • 키워드 = 공백으로 나누고(split) 소문자로(lower)
  • 검색 O(1) + 결과 수 / 순회 검색 O(N × 메시지 길이)
  • 대신 커밋할 때 조금 일을 더 함
